# Путь Маугли — вариант «один файл» для GitHub Pages

Вся база знаний собрана в один `index.html`: стили, скрипты и все 15 изображений лежат внутри файла. Нет папок `src/` и `assets/` — значит, нечего потерять при загрузке. Именно этот вариант берите, если многофайловая версия на GitHub открывается пустой страницей.

**Размер:** ~4 МБ (лимит GitHub Pages — 1 ГБ на сайт).
**Проверено:** 26 сценариев на 1440 и 390 px, ошибок нет; внешних запросов нет.

## Как опубликовать

1. Создайте публичный репозиторий, например `mowgli-path`.
2. Загрузите в **корень** репозитория три файла: `index.html`, `.nojekyll`, `README.md`.
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch**.
4. Ветка `main`, папка `/ (root)`, **Save**.
5. Через 1–2 минуты: `https://<username>.github.io/<repo>/`.

Скрытый `.nojekyll` при перетаскивании файлов в браузер часто не загружается. Если его нет — **Add file → Create new file**, имя `.nojekyll`, содержимое пустое, Commit.

## Если страница всё равно не открывается

Проверяйте по порядку — это закрывает почти все случаи.

| Что видно | Причина | Что сделать |
|---|---|---|
| 404 | Файлы лежат во вложенной папке, а не в корне | В корне репозитория должен быть именно `index.html` |
| Пустой экран или «Для навигации нужен JavaScript» | Загружена только оболочка без `src/` и `assets/` | Возьмите этот однофайловый вариант |
| 404, в Actions пусто | Source = GitHub Actions, но workflow не загружен | Выберите **Deploy from a branch** |
| «There isn't a GitHub Pages site here» | Pages ещё не включён или идёт первая сборка | Подождите 2 минуты, обновите Settings → Pages |
| Ошибка про ветку | Ветка называется `master`, а не `main` | Укажите ту ветку, которая реально есть |
| Pages недоступен | Репозиторий приватный на бесплатном плане | Сделайте репозиторий публичным |

Ещё проверьте: имя файла — строчными буквами `index.html` (не `Index.html`), а страница открывается по адресу репозитория, а не по прямой ссылке на файл.

## Навигация

Внутри — хеш-маршруты: `#/path`, `#/tools`, `#/tool/<id>`, `#/case/c06`, `#/archetypes`, `#/about`, `#/authors`. Работают на Pages без настройки сервера. Адреса без `#` (например `/tools`) GitHub Pages не знает и отдаст 404 — это нормально для статики.

## Что внутри

- `index.html` — весь сайт: 9 кейсов, 35 инструментов, 4 архетипа, 8 авторов, блок автора идеи с фото и контактами.
- `.nojekyll` — отключает обработку Jekyll.
- Печать инструмента — кнопка «Распечатать инструмент» на странице инструмента.

## Обновление

Это готовая сборка: править её вручную неудобно. Правки делайте в исходниках (`mowgli-kb/`), затем пересоберите:

```
multitool-node --skill websites site.cjs bundle "mowgli-kb/index.html" "put-maugli.html"
multitool-node --skill websites verify.cjs "put-maugli.html" --actions "mowgli-kb/src/actions.json"
```

и замените `index.html` в репозитории.

## Ограничения

- Репозиторий и сайт публичны — не добавляйте персональные данные.
- Внешние ссылки (VK, Telegram, подкаст) открываются у посетителя; доступность самих сервисов сайт не проверяет.
- Дисклеймер в подвале сохранён: это не методика и не замена супервизии.
